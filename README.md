# GST Compliance Risk Assessment — GNN + Isolation Forest

Interpretable risk assessment for GST compliance, combining a GraphSAGE
Graph Neural Network (taxpayer similarity graph) with Isolation Forest
anomaly detection, plus a Streamlit UI for scoring uploaded taxpayer data.

Built against the real **GST-Predictive-Dataset-2024** (anonymized:
`Column0`..`Column21`, `ID`, `target`), with a class-conditional
bootstrap-resampled synthetic taxpayer population used to densify the
graph and give the model more risky examples to learn from.

## Setup

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

If `torch_geometric` fails to install via pip on your platform, follow the
platform-specific instructions at https://pytorch-geometric.readthedocs.io
(CPU-only works fine for this project's scale).

## 1. Add the real dataset

Place these four files in `data/raw/` (exact names matter — see `src/config.py`):

```
data/raw/X_Train_Data_Input.csv
data/raw/Y_Train_Data_Target.csv
data/raw/X_Test_Data_Input.csv
data/raw/Y_Test_Data_Target.csv
```

Note: unlike a typical Kaggle test set, `Y_Test_Data_Target.csv` here
contains real labels — a genuine labeled holdout, not a blind competition
file. The pipeline still treats test nodes as unlabeled during graph
construction and GNN training; the labels are only used afterward, in
Phase 3, to report true held-out performance.

## 2. Run Phase 1 alone (optional — fast, no GNN)

```bash
python run_phase1.py
```

Loads the real data (stratified-subsampled per `MAX_TRAIN_ROWS` /
`MAX_TEST_ROWS` in `src/config.py`, default 20,000 / 5,000 rows), runs a
full EDA (5 plots to `outputs/plots/`), fits the class-conditional
synthetic generator, generates synthetic rows, validates them
numerically and visually against the real data, and saves the combined,
preprocessed feature matrix to `data/processed/`.

Runtime: well under a minute on a normal laptop.

## 3. Run the full pipeline (trains the model)

```bash
python run_pipeline.py
```

Runs Phase 1, builds the k-NN taxpayer graph, trains the GraphSAGE GNN
(150 epochs, early-stopped on validation ROC-AUC) and Isolation Forest,
evaluates on both an internal holdout and the **real** test labels, and
saves every artifact to `models/` (encoder, scaler, GNN weights,
Isolation Forest, a reference node pool for inductive inference).

**Expected runtime: a few minutes on CPU** (mostly GNN training over
~65,000 graph nodes at the default config). To go faster for a quick
check, lower `MAX_TRAIN_ROWS` / `GNN_EPOCHS` in `src/config.py` first.
To use the full 785K/262K-row dataset instead of the default subsample,
set `MAX_TRAIN_ROWS = None` and `MAX_TEST_ROWS = None` — this is
substantially slower (the k-NN graph build is the main bottleneck).

## 4. Run the Streamlit app

```bash
streamlit run app/streamlit_app.py
```

Requires `models/` to already be populated (step 3). Upload a CSV with
the `Column0`..`Column21` schema (an `ID` column is optional) and get
back a risk score, risk tier, GNN probability, anomaly score, and (if
enabled) the top contributing features per row — computed by attaching
new rows inductively to the trained reference graph, no retraining
required.

## Design notes worth knowing before you present this

- **Synthetic data is class-conditional bootstrap, not invented
  distributions.** Since the real columns are anonymized, the generator
  is fit directly on the real training data: it draws a synthetic
  `target` first, then resamples every column from its real empirical
  distribution *conditional on that class* (continuous columns get small
  jitter; discrete/binary columns are resampled as-is). This was an
  explicit fix — an earlier version generated features independently
  and derived labels from a weighted linear combination, which
  systematically weakened strong real relationships (e.g. `Column18`,
  the strongest real predictor at r=0.74, only reproduced r=0.55 under
  that approach vs. r≈0.72 with class-conditional bootstrap). See
  `src/phase1_data/synthetic_generator.py` docstring for the full story.
- **A few fat-tailed columns (5, 9, 14, 15) won't perfectly match real
  std.** These have a handful of extreme real outliers dominating their
  variance — no resampling method reliably reproduces single-in-100,000
  events at moderate sample sizes. Medians match closely; this is
  flagged in `validate_against_real()`'s output, not hidden.
- **Leakage prevention is structural.** The encoder/scaler/outlier-clip
  bounds are fit once on the training split and threaded explicitly
  through every downstream call (including the Streamlit upload path) —
  never refit on validation/holdout/test/new data.
- **`predict_for_new_data` is inductive, not transductive.** GraphSAGE
  (not GCN) was chosen specifically so new, previously-unseen rows can
  be embedded and scored by attaching them to a saved reference graph
  via k-NN edges, without retraining — see
  `src/phase2_graph_model/graph_builder.py:attach_new_nodes_to_reference_graph`.
- **GNNExplainer is a custom, lightweight implementation** (mask-learning
  over a node's incident edges and features), not `torch_geometric.explain`
  — the official API has changed across PyG versions and wasn't stable
  enough to depend on for a submitted project. Documented in
  `src/phase3_pipeline/explainability.py`.

## Sandbox note

The plots and validation numbers already in `outputs/` and
`data/synthetic/` were generated at the real config scale (20,000
training rows). The full trained model (GNN + Isolation Forest weights
in `models/`) was **not** shipped in this zip — training takes a few
minutes, which exceeded the sandbox environment's per-command time limit
where this was built. Run `python run_pipeline.py` yourself to produce
those artifacts; the code has been verified end-to-end (including the
`load()` → `predict_for_new_data()` → Streamlit inference path) at a
reduced scale, so this is purely a runtime issue, not a correctness one.
